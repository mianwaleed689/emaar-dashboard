The insight
You already built the target pattern.

src/admin/DataManagerV2/ is the clean architecture: 100-line router, each section in its own file, each section subscribes directly to Firestore, receives 2 props not 30. The mission isn't to invent something new — it's to finish migrating the rest of the platform to match what you've already proven works.

The three blockers

Blocker 01 · The Dashboard God Component
EmaarDashboardV2.jsx is a 6,024-line monolith.
417 useState hooks  ·  39 onSnapshot subscriptions  ·  33 tabs, each receiving 20-50 props

Every keystroke in any filter re-renders the whole shell, re-evaluates all 417 state values, and re-passes all props to all 33 tabs. This is why the app feels heavy and why you can't add a tab without editing a massive file.

Blocker 02 · The Admin Panel is Even Worse
AdminPanel.jsx is 22,365 lines.
439 useState hooks  ·  Theme duplicated inline (should import from theme.js)  ·  Old patterns + DataManagerV2 mixed in same file

Same disease, 3.5x the scale. Includes an AdminPanel.jsx.backup file committed to git — backups belong in git history, not your repo.

Blocker 03 · Fragmented Data Layer
Seven data files and no single source of truth.
data.js · data_developers.js · data_emaar_complete.js data_master.js · communities/*.js · data/projects/ (new)

Golf Grand's wrong data sits in data.js line 21 (construction 96%, price 1.53M) while the corrected record sits in data/projects/. Both are imported somewhere. This is bug soil — and it's why one wrong RERA number hid in production for months.

01
Extract the Dashboard Shell
1 week · after Phase 0
◆ Next
Goal: Shrink EmaarDashboardV2.jsx from 6,024 lines to under 300.

Strategy

Move state ownership from shell into tabs using the DataManagerV2 pattern. Each tab becomes responsible for its own Firestore subscriptions via shared hooks.

Create shared data hooks (src/hooks/data/)

export function useProjects() { const [data, setData] = useState([]); useEffect(() => { const unsub = onSnapshot(collection(db, "projects"), snap => { setData(snap.docs.map(d => ({ id: d.id, ...d.data() }))); }); return () => unsub(); }, []); return { data, loading: data.length === 0 }; }

Migrate tabs (easiest → hardest)

  • Day 1-2: CurrencyTab, MortgageTab, MarketTab, OverviewTab
  • Day 3: YieldsTab, DLDVolumesTab, NeighbourhoodsTab
  • Day 4-5: ProjectsTab, HandoverTab
  • Week 2+: LaunchCalendarTab (split into 3 components)

Success metric: EmaarDashboardV2.jsx under 500 lines. No tab receives more than 5 props.

02
Migrate Admin Panel
1-2 weeks · after Phase 1
Later
Goal: Same treatment for AdminPanel.jsx (22K → 500 lines).

Reuse everything from Phase 1 — same hook pattern, same shell, same config. Split by admin function area: User management, Billing, Operations, Content (DataManagerV2 already here ✓), Intelligence.

Success metric: AdminPanel.jsx under 500 lines. Zero state lives in the shell.

03
Data Catalog at Scale
2-3 weeks · after Phase 2
Later
Goal: Move from 3 curated projects to a unified catalog of 100-500 verified projects, Firestore-first.
  • All projects in Firestore; seed files are bootstrap-only
  • Admin workflow: DataManagerV2 form validates against audit rules live
  • Auto-enrichment pipeline (DLD + Google Places + transaction data)
  • CatalogHealth admin section: top offenders, rule violations, stale data
  • Source attribution per field with confidence scoring

Success metric: 100% of published projects have _audit.dataQuality: "high".

Kill the .backup

02
Delete unused data

03
Merge context/ folders

04
Remove empty folders
services/api/, components/layout/, etc. — all .gitkeep only. Delete.
05
Drop react-scripts
You use Vite now. Remove react-scripts dependency — 200MB saved.
